# جرس الحصص — School Bell

تطبيق Flask/PWA يعرض تنبيهاً نصياً وصوتياً عند نهاية كل حصة وبداية التي تليها، لكل شعبة صفية. يعمل أوفلاين بالكامل بعد أول تنزيل للجدول.

## التشغيل محلياً

```bash
pip install -r requirements.txt
python app.py            # http://localhost:5000  (SQLite محلي bell.db)
```

- لوحة الإدارة: `/admin` (افتراضياً `admin` / `admin` — غيّرها عبر `ADMIN_USER` و`ADMIN_PASS`)
- دخول الأجهزة بالكود: `/login` ← شاشة التنبيه `/app`

## النشر على Render

1. أنشئ Postgres (Render أو Neon) وضع الرابط في `DATABASE_URL`.
2. اضبط `SECRET_KEY` و`ADMIN_USER` و`ADMIN_PASS`.
3. `render.yaml` جاهز؛ الجداول تُنشأ تلقائياً عند أول تشغيل.

الشعارات والخلفيات والنغمة تُخزَّن داخل Postgres (وليس على القرص) لأن قرص Render يُمسح مع كل نشر.

## ترتيب الإعداد في لوحة الإدارة

1. **المراحل** ← أضف المرحلة وحدد أيام الدوام.
2. **الحصص** ← بداية الدوام + مدة كل حصة/استراحة. الحصص متتالية بلا فراغ، فالتوقيتات تُحسب تلقائياً.
3. **يوم بتوقيت مختلف للمرحلة** (اختياري) ← مثلاً الخميس بحصص أقصر.
4. **الصفوف والشعب** ← يُولَّد كود لكل شعبة تلقائياً. ويمكن تخصيص توقيت صف معيّن ليوم أو لكل الأيام.
5. **المعلمون** ← الصق الأسماء (اسم بكل سطر)، ثم اربطهم بالشعب من شاشة الشعبة أو شاشة المعلم.
6. **الأكواد** ← صفحة واحدة لكل الأكواد مع نسخ وطباعة.
7. **النغمة والأجهزة** ← استبدال النغمة ومتابعة آخر مزامنة لكل جهاز.

أولوية التوقيت: برنامج الجرس المسند للصف في ذلك اليوم ← تخصيص الصف ← يوم المرحلة ← الافتراضي.

### برامج الجرس
برنامج الجرس قائمة كاملة بالحصص والفرص وتوقيتها، مثل «الصفوف 3+4» و«الصفوف 3+4 — الثلاثاء». يُسند لكل صف برنامج لكل يوم من **برامج الجرس ← توزيع البرامج**. فيمكن أن يتبع صفان من مرحلتين مختلفتين البرنامج نفسه، وأن يختلف موضع الفرصة يوم الثلاثاء.
الاستيراد والتصدير عبر ملف Excel فيه ورقتان: «البرامج» (سطر لكل حصة) و«التوزيع» (سطر لكل صف وخانة لكل يوم). يُنشئ الاستيراد المراحل والصفوف الناقصة.

## كيف يعمل التنبيه

- الجهاز يسجّل دخوله بالكود مرة واحدة (جلسة 365 يوماً)، ينزّل الجدول ويحفظه في IndexedDB.
- التنبيه يُحسب من ساعة الجهاز مقابل الجدول المحفوظ — لا يعتمد على السيرفر وقت الحصة.
- عند توفر الإنترنت يُحدَّث الجدول بصمت كل 5 دقائق (فقط إن تغيّر شيء، عبر `schedule_version`).
- الحصص المتتالية تعطي تنبيهاً واحداً: «انتهت الحصة الأولى - بداية الحصة الثانية»، وآخر حصة: «انتهت الحصة الثالثة».
- كود المعلم يجمع تنبيهات كل شعبه؛ التنبيهات المتطابقة في نفس الدقيقة تظهر مرة واحدة.
- إعادة توليد كود من الإدارة توقف الكود القديم؛ الجهاز يُظهر تنبيهاً ويستمر بالجدول المحفوظ حتى يُدخل الكود الجديد.

## تجهيز الشاشة الثابتة في الصف (Kiosk)

- المتصفحات تمنع الصوت حتى أول لمسة، لذلك تظهر شاشة «ابدأ» بعد كل تشغيل للتطبيق — المسة واحدة تكفي.
- للتابلت/الـ mini PC بدون لمس: شغّل Chrome بالخيار `--autoplay-policy=no-user-gesture-required --kiosk https://<الموقع>/app`.
- التطبيق يطلب إبقاء الشاشة مضاءة (Wake Lock). عطّل وضع السكون وتوفير البطارية للمتصفح على التابلت.
- تأكد أن ساعة الجهاز مضبوطة تلقائياً (Network time) وأن المنطقة الزمنية Asia/Amman.

**حدود معروفة للمتصفح:** على الموبايل يعمل تنبيه الـ PWA والتطبيق مفتوح في الواجهة فقط، لأن المتصفحات توقف المؤقتات في الخلفية. للتنبيه بالخلفية استخدم التطبيقات الأصلية أدناه.

## التطبيقات الأصلية — تنبيه بالخلفية وفي موعده وبدون إنترنت

الإنترنت مطلوب **لأول تسجيل دخول فقط**. بعدها تُسجَّل كل التنبيهات في نظام التشغيل كتنبيهات **أسبوعية متكررة**، فتستمر أسابيع وأشهر بلا إنترنت، حتى لو لم يُفتح التطبيق. عند توفر الإنترنت يُحدَّث الجدول بصمت، ويُعاد التسجيل تلقائياً إن تغيّر شيء من لوحة الإدارة.

| النظام | كيف يرن في الموعد | الملف |
|---|---|---|
| Android | `AlarmManager.setAlarmClock` (نفس آلية تطبيقات المنبّه: دقيق بالثانية، لا يتأثر بوضع توفير الطاقة Doze). يُعاد تسليحه للأسبوع التالي بعد كل رنّة، وبعد إعادة التشغيل أو تغيير الساعة. | APK |
| iPhone/iPad | إشعار محلي بمحفّز تقويم متكرر أسبوعياً يديره iOS نفسه | يحتاج حساب Apple |
| Windows/Mac | تطبيق في شريط المهام يبدأ مع الجهاز؛ في الموعد نافذة ملء الشاشة فوق كل النوافذ + النغمة، على كل الشاشات | EXE / DMG |

### البناء (بدون تثبيت أي SDK)
1. ارفع المشروع على GitHub.
2. أضف متغير المستودع `BELL_SERVER` = عنوان السيرفر على Render (Settings ← Secrets and variables ← Actions ← Variables).
3. من تبويب Actions شغّل:
   - **Android APK** ← ملف `app-debug.apk` قابل للتثبيت مباشرة.
   - **Desktop installers** ← `.exe` لـ Windows و `.dmg` لـ Mac.
   - **iOS build check** ← يتحقق من بناء iOS. التثبيت على أجهزة Apple يحتاج حساب Apple Developer، ثم يُفتح `mobile/ios/App` في Xcode للتوقيع والتوزيع عبر TestFlight.

### إعداد أول مرة على Android
بعد الدخول بالكود يعرض التطبيق خطوة أخيرة:
- **السماح بالإشعارات.**
- **«المنبهات والتذكيرات»** (يُمنح تلقائياً على Android 13+).
- **إلغاء قيود البطارية:** ضروري في Samsung وXiaomi وHuawei، لأنها تقتل التطبيقات في الخلفية.

### قيود يجب معرفتها
- **iPhone في الوضع الصامت:** يظهر الإشعار بدون صوت. تجاوز ذلك يحتاج صلاحية Critical Alerts من Apple.
- **iOS:** يحتفظ بـ 64 تنبيهاً كحد أقصى. الأسبوع الدراسي العادي (مثلاً 5 أيام × 9 تنبيهات = 45) يتسع بالكامل كتنبيهات متكررة. معلم مرتبط بمراحل متعددة بأوقات كثيرة جداً يتحول تلقائياً إلى أقرب 60 تنبيهاً، وتتجدد كلما فُتح التطبيق.
- **الكمبيوتر:** لا يرن وهو نائم أو مغلق الغطاء. تنبيه فاتته أكثر من 90 ثانية لا يُعاد متأخراً.
- **النغمة:** في التطبيقات الأصلية النغمة مدمجة بالتطبيق. النغمة المرفوعة من لوحة الإدارة تُستخدم في الـ PWA وتطبيق الكمبيوتر.
- **ساعة الجهاز:** يجب أن تكون على «الوقت التلقائي» ومنطقة Asia/Amman.

## الاختبارات

```bash
python -m pytest tests                  # الـ backend: CRUD، التوقيتات، الأكواد، المزامنة، الرفع، مصادقة التطبيقات
node tests/test_alerts.js               # منطق التنبيه والخطة الأسبوعية
node tests/test_bridge_mobile.js        # ما يُسجَّل في Android/iOS
node tests/test_desktop_scheduler.js    # مؤقت تطبيق الكمبيوتر
python tests/e2e_browser.py             # PWA في Chrome: دخول، تنبيه، ثم أوفلاين كامل
python tests/e2e_mobile_web.py          # طبقة التطبيق: دخول عبر نطاق مختلف، تسجيل التنبيهات، إعادة فتح أوفلاين
python tests/e2e_desktop.py             # تطبيق الكمبيوتر الحقيقي: يُطفأ السيرفر ثم يرن التنبيه بموعده
```
